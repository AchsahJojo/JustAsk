Bugs that change what she experiences
Voice commands eat real requests. packages/core/src/commands.ts matches again, repeat, cancel, stop, stuck, and can't find anywhere in the sentence, before a session can start. packages/core/src/controller.ts input() then calls repeat(), stop(), or stuck() and returns. On the start screen those do nothing:
"help me cancel my subscription" stops
"I can't find the pharmacy page" is stuck
"refill it again" is a repeat, and again also matches inside other words
During a clarify question, "the bus stop on Main" stops the session. The unit test only checks "help me refill" as free text.
Identical buttons are thrown away before the fingerprint can tell them apart. packages/page-agent/src/scanner.ts drops a second control with the same role, visible text, and href. Two "Refill" or "Edit" buttons with no href collapse to the first one in document order. The nearby heading (the drug name, the row) is not part of that key. The fingerprint in packages/page-agent/src/fingerprint.ts was built to keep those rows distinct, and it never sees the second button. The ranking table in docs/refined-plan-1.md says to collapse duplicates; the fingerprint section says to keep them. Those two parts of the spec disagree.
Caregiver tasks vanish. Starting a task sets it to active (apps/extension/src/lib/session.ts). The panel only loads pending (packages/backend/convex/tasks.ts). packages/backend/convex/sessions.ts sets the task to done only on a done event. Stop, abandon, a risk "No", or a blocked step leaves it active forever, so the card never comes back. "Later" writes pending again, which it already is, and only hides the card until the next poll. dismissed exists on the schema and is never used.
Long or truncated dropdowns can trap her. Option labels are clipped to 60 characters, and lists over 30 send only the first 10 (packages/page-agent/src/scanner.ts). The live check compares the full option text (packages/page-agent/src/agent.ts). A correct choice whose label was clipped never matches, and every change sends ja:wrong. For lists over 30, packages/shared/src/step.ts checkStep skips the exact-option rule, so a made-up option is accepted and the same loop follows.
Placeholder selects look already filled. hasValue for a <select> is true when the first option's value is not "". A real placeholder (<option>Select a state</option>) has no value attribute, so the value is the text itself. The prompt then says not to ask again when hasValue and valid are both true. The fixtures use value="", so tests miss this.
A mismatched snapshot id hangs the session. In requestStep, if (res.snapshotId !== snapshot.snapshotId) return leaves the phase on planning with no retry and no spoken line (packages/core/src/controller.ts around line 397). Both planners echo the id today, so this only fires if a response is mixed up.
Hover finishes after the pointer has left. The hover timer starts on pointerover and is never cleared on leave (packages/page-agent/src/agent.ts). A brief pass over the control still completes 300ms later. There is no unit test for hover or for expect: "file".
Clarify input loses focus. A useEffect in apps/extension/src/ui/Panel.tsx focuses the caption whenever the spoken line changes, after the answer box's autoFocus.
"I'm done typing" does not re-check the field. doneTyping() always completes the step. The plan says the step advances only when hasValue is true. The done screen also calls typing, choosing, and hover "clicks".
Privacy and trust gaps
Typed text can still leave the page. Native input .value is not used as a label, and the sentinel test covers the nested-<p> case. These paths still copy text into the snapshot via innerText:
A contenteditable root itself (<p contenteditable>) is not skipped. insideEditable only looks at the parent.
A <label> that wraps a contenteditable includes the typed text.
On-page [role=alert] / [role=status] text is sent even when the site quotes what she typed. .validationMessage itself is never read, which is the rule, and this is the same kind of string rendered by the page.
The snapshot is a Convex action argument. packages/backend/convex/plan.ts passes the whole POST body (page text, element text, URL, device token) into plan.run. The handler's own console.log is only stop reason and token counts. Convex execution logs record function arguments, which is the channel the rule says snapshots must not enter. The local planner also keeps every body in memory and serves GET /__received with Access-Control-Allow-Origin: * while planner:dev is running.
A suspicious step can speak the model's instruction. If risk is suspicious and say is still "Click Buy gift cards", that line is spoken. The session does not highlight. Caregiver notification runs for done and stuck only, so a blocked suspicious step does not notify even when notifyOnStuck is on.
Pairing codes are six digits from Math.random, public, and unlimited. packages/backend/convex/devices.ts redeemCode has no attempt counter. Redeeming it returns a device token that can read tasks, start sessions, change consent, and complete tasks. A code collision makes .unique() throw, so neither senior can redeem.
checkStep does not check that expect fits the control. A guide step may say type at a link or click at a disabled button. She can be pointed at a control that will not activate. Checkbox, radio, and file fields are also described to the model as "has text" or "empty", because hasValue for those is "checked" or "has a file".
Edges the plan describes and the code does not finish
ja:page-changed is never sent. The type exists in packages/shared/src/messages.ts and the controller handles it. What actually fires is any tab status === "complete" while guiding or waiting, including a late iframe load, which can drop the current highlight and record "the page changed before she clicked" even when she did click and the content script died first. SPA pushState does not update tab status, so a wait step sits on "I'm ready" until she presses the button. The mutation observer is on the document only, not inside shadow roots.
ja:clicked is never sent. The 5-second new-tab follow window only starts if ja:step-done arrives, so a slow message can miss a new tab.
Iframes are merged top-frame-first up to 150, with no second ranking pass (packages/core/src/merge.ts). A busy parent can crowd out a button that lives in a child frame. visibleFrames is computed and never used, so frames smaller than 50×50 are not skipped. about:blank / srcdoc injection is not implemented. Controls inside an iframe are judged against that frame's own viewport, and nothing scrolls the parent to reveal them.
Shadow DOM is half-handled. Clickable elements walk open and closed roots. Modal detection, page text, headings, and fingerprint closest() use light-DOM queries, so a dialog inside a component does not hide the rest of the page, and the model sees the buttons without the words around them. The e2e closed-shadow ring check is swallowed with .catch(() => {}).
Dock mode, popup-window sign-in, and "continue on the child tab" are specified and not built. panelKind() can return "dock", and sidepanel.html is web-accessible for it. Closing the session tab only pauses.
Recognition is not muted while JustAsk speaks. Combined with the command regex, a picked-up "stop" or "again" ends or ignores the turn.
colorName only parses rgb() / rgba(). oklch(), lab(), and color(srgb …) become "no color", so the spoken line cannot say "the blue button" on a lot of current CSS.
The overlay calls scrollIntoView. Guide mode forbids clicks, typing, and submit. Scrolling the target on screen is extra, and it is what makes the ring visible. Worth deciding whether that counts as acting for her.
Recipe startUrl is an unconstrained string and tabs.update navigates the session tab there. That matches the plan (caregiver recipe, same tab). There is no allowlist.
What holds up
Element numbers are renumbered per snapshot and mapped back to (frameId, localId). Password, email, and file names are not copied for the structures the tests build. Risk steps for money, personal info, and account changes ask before highlighting. A stale in-flight plan after Stop is ignored via the generation counter. Fingerprint rebinding works when exactly one node matches. chrome.* stays in the extension. packages/core talks to a PageBridge
